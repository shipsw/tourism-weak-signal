# 出入境旅游弱信号发现与研判 Agent — 技术设计方案

> 版本：v0.1（MVP 阶段）
> 依据：《出入境旅游弱信号发现与研判Agent设计方案.md》

---

## 1. 系统概述

### 1.1 定位

系统从全球网络信息中自动发现**尚未形成热点、但具有趋势性与苗头性**的出入境旅游相关信息，为文旅研究人员提供**每日观察素材**。

核心定位是 **AI 研究助理**，而非舆情监测系统：

| 维度 | 舆情监测 | 本系统 |
|------|---------|--------|
| 关注对象 | 热点、热搜、大 V | 早期苗头、群体性反馈、趋势变化 |
| 时间窗 | 事件发生后 | 事件形成前 / 形成早期 |
| 输出 | 热度排行、情感分析 | 弱信号研判、观察建议 |
| 存储 | 大数据平台 | 当日报告 + 少量历史索引 |

### 1.2 核心流程

```
每日任务 → 信息发现 → 初筛过滤 → 弱信号判断 → 趋势研判 → 日报生成
```

### 1.3 设计原则

1. **轻量**：不做全网采集、不建大数据仓库、不做热度系统。
2. **可解释**：每条弱信号附判断理由（新颖/重复/扩散/影响/持续 五维评分）。
3. **可扩展**：数据源、Agent、评分权重均可配置化扩展。
4. **低成本**：默认使用免费 RSS / 公开 API，LLM 采用批量调用。

## 3. 数据模型

### 3.1 候选信息 NewsItem（Agent1 输出）

```json
{
  "title": "标题",
  "content": "摘要/正文片段",
  "url": "来源链接",
  "source": "来源平台（google_news/reddit/...）",
  "published_at": "发布时间 ISO8601",
  "language": "zh/en",
  "keywords": ["免签", "入境游"],
  "raw": {}
}
```

### 3.2 过滤结果 TourismFilterResult（Agent2 输出）

```json
{
  "tourism_related": true,
  "direction": "入境中国 | 出境中国 | 双向 | 其他 | 不确定",
  "type": "游客行为 | 政策 | 航线 | 目的地 | 体验反馈 | 产业动态 | 其他",
  "reason": "判断依据"
}
```

### 3.3 弱信号评分 WeakSignalScore（Agent3 输出）

五维评分，每维 0-10 分：

| 维度 | 含义 | 默认权重 |
|------|------|---------|
| 新颖性 novelty | 是否出现新的趋势/变化 | 0.25 |
| 重复性 repetition | 是否多个来源出现类似信息 | 0.20 |
| 扩散性 diffusion | 是否跨平台、跨地区传播 | 0.15 |
| 影响性 impact | 是否可能影响出入境旅游发展 | 0.25 |
| 持续性 sustainability | 是否可能持续发展 | 0.15 |

总分 = Σ(维度分 × 权重)，分级：

| 总分 | 级别 | 处理 |
|------|------|------|
| 0-3 | 普通信息 | 不进入日报 |
| 4-6 | 观察信息 | 进入日报「其他值得关注」 |
| 7-10 | 重点关注 | 进入日报「重点关注趋势」 |

### 3.4 SQLite 表结构

```
candidates         候选信息（当日全部）
  id / title / content / url / source / published_at / language / keywords / date

assessments        过滤+评分结果
  id / candidate_id / tourism_related / direction / type /
  novelty / repetition / diffusion / impact / sustainability /
  total / level / reason / signal_summary / date

reports            日报索引
  id / date / path / summary
```

保留策略：candidates/assessments 保留 30 天；reports 长期保留。

## 4. 数据源设计

### 4.1 Source 抽象接口

```python
class BaseSource(ABC):
    name: str
    def fetch(self, date: str) -> list[NewsItem]: ...
```

新增数据源只需实现 `fetch()`，并在 `sources/registry.py` 注册。

### 4.2 MVP 数据源

| 来源 | 实现方式 | 说明 |
|------|---------|------|
| Google News RSS | feedparser | 免密钥，中英文关键词组合，覆盖国际媒体与国内新闻转载；自动追加 `after:YYYY-MM-DD` 限定最近 N 天 |
| Google News 社交定向 | feedparser + site: 语法 | 免密钥抓取 Quora / X / Facebook / YouTube / 微博 / 小红书 被索引内容，第一手弱信号；同样限定时间窗口 |
| Reddit | requests + OAuth | 官方 API（免费档，需注册应用），旅游社区早期讨论；未配密钥时匿名请求可能被 403 |
| 国内平台 | 预留接口 | 今日头条/微博等私有接口或搜索代理，MVP 阶段以 site:weibo.com 等定向搜索部分覆盖 |

> **时效性（实测）**：Google News RSS 默认按相关性排序，不加过滤时旧内容（数月前）会混入结果，
> 社交定向查询（site: 语法）尤其明显。因此每个查询自动追加 `after:YYYY-MM-DD`（`lookback_days` 配置，默认 3 天），
> 抓取后按 published 字段兜底过滤。实测 291 条候选 100% 落在 72 小时内，
> 且相比无过滤模式（78 条）候选量更大、出现了此前没有的“重点关注”信号——时效性对弱信号发现价值显著。

> **社交平台可行性（实测）**：Quora/微博/X/Facebook 可经 Google News `site:` 语法免费获取；
> Reddit 不被 Google News 索引，需官方 API（免费档 OAuth，`.env` 配 `REDDIT_CLIENT_ID/SECRET`）；
> X 官方搜索 API 为付费档，免费替代方案仅有 site: 定向搜索（噪声大，依赖过滤 Agent 清洗）；
> Facebook 无公开搜索 API，仅能覆盖被索引的公开帖子。

> **国内平台（头条/抖音/小红书/微博）无公开稳定 API**，是 MVP 最大不确定点。
> 备选方案：① 自建搜索代理页面采集（合规风险需评估）；② 使用搜索聚合 API；③ 先用 Google News/Bing News 中文搜索 + site: 定向搜索覆盖。

### 4.3 关键词体系（config.yaml 可配）

中文组：入境旅游、出境旅游、外国游客、免签、144小时过境免签、航线开通、旅游体验...

英文组：China tourism、visa-free China、inbound tourism、Chinese tourists overseas、travel experience...

> 关键词按「政策/行为/体验/航线/目的地」分类维护，便于 Agent 溯源。

## 5. Agent 设计

### 5.1 Agent1 信息发现 DiscoveryAgent

- **输入**：日期、config 中启用的数据源与关键词
- **处理**：并发调用各 Source.fetch()，按 URL 去重、按日期过滤
- **输出**：100-300 条 NewsItem
- **实现要点**：请求超时与重试、单源失败不阻塞整体

### 5.2 Agent2 旅游过滤 FilterAgent

- **输入**：NewsItem 列表
- **处理**：LLM 批量判断是否属于出入境旅游领域；过滤普通社会新闻、非旅游移民问题
- **输出**：tourism_related / direction / type / reason
- **实现要点**：批量 Prompt（每批 5-10 条）降低成本；`tourism_related=false` 直接丢弃

### 5.3 Agent3 弱信号判断 WeakSignalAgent

- **输入**：过滤后的候选 + 当日重复计数（跨源、跨地区统计）
- **处理**：
  1. 按主题聚类（相同/相似信息归为一组）
  2. LLM 对每组做五维评分
  3. 结合客观重复计数校正重复性/扩散性分数
- **输出**：WeakSignalScore 列表
- **核心思想**：单条投诉价值低；多国游客、多平台出现类似体验问题，价值提高

### 5.4 Agent4 日报生成 ReportAgent

- **输入**：重点关注信号 + 观察信号
- **输出**：Markdown 日报（见 §8）
- **实现要点**：只把 7-10 分信号放入「重点关注趋势」，4-6 分放入「其他值得关注」，避免噪音

## 6. LangGraph 工作流

```python
State = {
  "date": str,
  "candidates": list[NewsItem],
  "filtered": list[FilteredCandidate],
  "signals": list[SignalGroup],
  "report": str,
}

workflow = StateGraph(AgentState)
workflow.add_node("discover", discovery_node)
workflow.add_node("filter", filter_node)
workflow.add_node("weak_signal", weak_signal_node)
workflow.add_node("report", report_node)
workflow.add_edge(START, "discover")
workflow.add_edge("discover", "filter")
workflow.add_edge("filter", "weak_signal")
workflow.add_edge("weak_signal", "report")
workflow.add_edge("report", END)
```

> 线性流程，每节点可在不改变接口的前提下替换为更复杂子图（如多路召回、历史比较）。

## 7. LLM 接入

### 7.1 统一接口

`llm.py` 封装 OpenAI 兼容的 chat/completions 接口：

```python
def chat_json(prompt: str, system: str, **kw) -> dict  # 强制 JSON 输出
def chat_text(prompt: str, system: str, **kw) -> str
```

- 通过 `.env` 配置 `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`
- 默认兼容：OpenAI、DeepSeek、Moonshot、Qwen（DashScope 兼容模式）、Ollama（OpenAI 兼容端点）

### 7.2 结构化输出与容错

- 优先使用 `response_format={"type":"json_object"}`（不支持时自动降级为文本）
- 解析失败时：剥离代码围栏 → 提取首个 `{...}` → 键名归一化（英文/中文键）
- 单条失败不阻塞流程，记录警告并跳过

### 7.3 成本控制

- 过滤/评分采用**批量 Prompt**（一次调用判断多条）
- 全文/长文先截断（默认 500 字符摘要）
- 弱信号分组评分，避免重复调用
- 每日预估 token 用量与费用写日志

## 13. 风险与对策

| 风险 | 对策 |
|------|------|
| 国内平台无公开 API | 先用中文聚合搜索覆盖；预留 Source 接口，评估合法代理方案 |
| LLM 幻觉/误判 | 五维评分附带理由；评分与客观重复计数结合；日报可溯源到 URL |
| 数据源不稳定 | 多源冗余、单源失败不中断、重试与超时 |
| API 成本 | 批量调用、截断、失败重试限制 |
| 时区/日期口径 | 统一使用 Asia/Shanghai 时区；按采集日归档 |
